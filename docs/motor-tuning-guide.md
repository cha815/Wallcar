# ID1 电机调参接口与使用说明

最新镜像改为主控速度PID输出力矩、报文Kp/Kd=0、固定5rad/s（已取消周期阶跃），UART7双通道：[主控PID定速说明](vofa-pid-step.md)。采用DIAG_MODE=6；下面DIAG_MODE=5及4为历史模式。

最新目标为上电自主运行10rad/s、Kd=1，UART7输出双通道JustFloat：见 [VOFA双通道说明](vofa-speed10.md)。新固件使用DIAG_MODE=5，包含80°C软件门禁；下面DIAG_MODE=4的15通道说明和5rad/s数据为此前调参模式记录。

当前目标：已架空ID1，MIT模式先调速度阻尼Kd，再调位置Kp/Kd。MIT没有积分增益Ki，不能把本次称作完整PID整定。

## 连接和构建

- MC02 **CAN1：PD0 RX / PD1 TX**；仲裁1Mbps、数据5Mbps。当前控制请求FD/BRS=off（请求整帧1Mbps），可接收电机BRS反馈；不声称当前控制发送已验证5Mbps BRS。
- UART7通过无线DAPLink映射到 **COM12**，115200/8N1；TX与RX都已实测。
- 当前已烧录镜像为 `DIAG_MODE=4 BUILD_DIR=build/reference-no-brs`，初始化 `FDCAN_FRAME_FD_NO_BRS`。默认`DIAG_MODE=0`不会自动运行调参。所有主循环接口非阻塞，ISR只搬运数据。
- `.ioc`已同步CAN1正确引脚和FIFO。CubeMX再生成会覆盖Makefile的自定义源列表/宏，需要保留自定义源和include配置并复核构建；不保证任意重新生成后自动保留构建集成。

## C接口

`app/motor_tune.h`提供`motor_tune_init(now)`、`motor_tune_tick(now,uart_errors)`、`motor_tune_arm(now)`、`motor_tune_velocity(v,kd,now)`、`motor_tune_position(relative,kp,kd,now)`、`motor_tune_stop(now)`和状态读取。

`device/motor.h`提供参数核对、反馈快照、MIT发送、使能/失能与取消；`component/motor_codec.h`负责封包、反馈解码和量化回解。业务不直接访问HAL。配置验证失败不会强行使用JSON替代实际量程。

## 串口命令（每行以LF结束）

| 命令 | 行为 |
|---|---|
| `PING` | 心跳；主机运行时每100ms发送，500ms失联停止 |
| `ARM` | 要求配置验证、反馈新鲜、失能、无故障且速度≤0.5rad/s；零目标后使能并等待反馈确认 |
| `VEL 1 0.5` | 速度目标1rad/s、Kd=0.5；Kp=0，力矩前馈0 |
| `POS 0.1 5 0.2` | 相对本次ARM位置+0.1rad，Kp=5、Kd=0.2 |
| `STOP` | 取消旧待发帧，再失能；需要新失能反馈与TX完成确认 |
| `CLEAR` | 停车确认、反馈新鲜且已失能时，显式清已知保护一次；等待新的无故障反馈，不改变保护参数、不写Flash、不自动使能 |
| `INFO` | 单次诊断帧，time_s=-1，其余通道为参数索引/值、TX/RX/错误和原始电机状态 |
| `READ 49` / `READ 50` | 只读过压/欠压阈值；只允许失能时读取 |
| `READ 66` / `READ 71` | 只读电机过温阈值/故障现场值；随后用INFO查看 |

速度目标±5rad/s，相对位置±0.5rad，Kp 0..5、Kd 0..2，速度斜坡10rad/s²。位置/速度目标保持受限，必要时降低增益；所有MIT命令按实际量化值复核预测力矩≤3Nm。该约束基于反馈，不能替代电机硬件限流/保护，也不保证两个反馈之间的瞬时力矩上限。

## VOFA+ JustFloat

选择COM12、115200、JustFloat；每10ms一帧，15个小端float32加尾部`00 00 80 7F`，共64字节：

| 通道（从0计） | 值 |
|---|---|
| 0 | 时间s；-1表示INFO诊断帧 |
| 1 / 2 | 最后成功提交的量化位置目标 / 实际位置rad |
| 3 / 4 | 最后成功提交的量化速度目标 / 实际速度rad/s |
| 5 | 实际扭矩Nm |
| 6 / 7 | 实际提交的量化Kp / Kd |
| 8 | 电机报告温度°C |
| 9 | 状态：0BOOT、1OFF、2ENABLING、3READY、4VEL、5POS、6STOPPING、7FAULT |
| 10 / 11 | 软件故障位 / 命令结果（1接受，-1格式/非法，-2当前状态不接受） |
| 12 / 13 / 14 | 真实使能反馈 / 反馈年龄ms / stop_confirmed |

FAULT不是停机确认。只有stop_confirmed=1、enabled=0且反馈年龄<200ms才能报告本次停止已确认。INFO帧不用于阶跃响应分析；主机脚本自动分离。

## 本轮参考框架与实测结果（2026-10-14）

采用父目录 `docs/底盘电机/code/component/mw_canQZB.c/.h` 原协议核心，发送、接收、状态命令由设备层适配 CAN1/ID1；保留已有单电机串口调参应用，未导入参考应用的 CAN3/四轮映射及启动自动清错。BSP拒绝BRS发送，HAL NO_BRS初始化后补写DBTP以保留电机BRS反馈的5Mbps接收时序，恢复时同样重配。

新镜像烧录校验成功。首轮目标0.5rad/s、Kd=0.2使能成功，但实际速度接近零。随后按用户指定目标5rad/s、Kd=1运行约5秒：运行末段1秒101个样本实际速度平均4.8095rad/s，范围4.6825～4.9365rad/s，误差约3.81%；温度34°C、故障0。结束后新鲜反馈确认失能。MIT的Kd速度阻尼存在负载相关稳态误差，本次不能称为完整PID整定或位置环验收。

原始数据：`evidence/reference-vel5-kd1.csv`；绘图使用从本次ENABLING附近开始的 `reference-vel5-kd1-active.csv`，排除无线DAPLink积存的先前失能报文；波形 `reference-vel5-kd1.png`。位置累计超过±12.5rad后反馈饱和，不能据此判断电机停止或计算继续转动的角度。

已烧录ELF SHA256：`9B36FD46D4E61D906695657CA8837F12071F1AB48E3FEC6960CE4BDACDBD8BD3`。审查要求的80°C软件台架温度门禁已加入源码并通过回归，但其最终构建执行被拒绝，尚未进入此镜像；本轮串口测试程序执行80°C使能门禁。后续烧录前需重新编译当前源码。

## 早期异常记录（本轮未复现，根因未证明）

7组主机测试通过，调参固件构建/烧录校验通过，FDCAN实际参数读取、状态反馈和串口JustFloat已运行。原PA11/PA12配置无法完成通信；改为MC02 CAN1 PD0/PD1后TX/RX一致，错误计数为0。

已确认初始CAN超时保护0x2000并显式清除；第一次ARM后电机立即返回 **0x0002（按所提供手册为母线过压）**，未接受速度目标。真实读回：过压阈值 **80.0V**，故障现场值 **100.0956V**，电机报告温度 **142°C**。用户确认24V电源，并用万用表测得供电端 **24.7V**，当前电机亮黄灯。故障现场是历史瞬时值，万用表的稳态读数不能排除瞬态；驱动采样/校准与协议版本含义也需核实。该矛盾尚未解决，不能靠调整Kp/Kd解释或关闭保护。

早期保护CSV与波形继续保留。本轮温度34°C、故障0且速度测试成功；这些结果不能证明早期100.10V/142°C记录的根因已找到。当前测试结束后失能，不自动重启。
