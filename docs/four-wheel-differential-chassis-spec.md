# 四轮差速胶轮底盘 spec

版本：v1 审阅稿；日期：2026-10-14。本文定义下一阶段底盘实现，本次交付不包含底盘控制代码或运动测试。

## 1. 目标、平台与边界

STM32H723 / MC02、STM32CubeH7 HAL、裸机主循环，四台泉智博电机共用 FDCAN1。提供前进、倒退、弧线转弯、原地转向、受控停止和故障处理。输入只定义 C API，不包含遥控、串口控制协议、里程计、IMU、风机或气压闭环。

轮径由用户确认为 **80 mm**，半径为 **0.04 m**。当前硬件仅接 ID1；ID2～4、轮位映射、方向和轮距尚未确认，不得将单电机通信结果当作四轮验收。

分层遵循项目架构：`main` 装配；`app/chassis` 负责整车策略和调度；`device/motor` 负责电机命令、状态与协议；`bsp` 负责硬件资源；运动学、限幅和斜坡置于独立 `component`。应用不访问 HAL、外设句柄或 CAN 原始报文。

## 2. 配置与运动学

| 参数 | 定义 / 默认值 | 使能条件 |
|---|---|---|
| `wheel_radius_m` | 固定 0.04 m | 不得沿用参考代码的115 mm轮径 |
| `track_m` | 左右轮接地点中心距，暂不填写 | 有限且大于0，实际测量确认 |
| `wheel[4].motor_id` | 固定轮位顺序 LF、RF、LR、RR；ID1～4的映射暂不填写 | ID唯一且完成接线核对 |
| `wheel[4].direction` | +1/-1，指令与反馈使用同一转换 | 逐轮架空测试确认前进方向 |
| `velocity_reference` | 输出轴或电机轴，暂不确认 | 必须确认实际协议语义 |
| `wheel_to_protocol_ratio` | 输出轴语义时1；电机轴语义时填写实测传动比 | 不直接复制20.25或重复应用减速比 |
| `geometry_confirmed` | 默认false | 上述项实测确认后才设true |
| `control_period_ms` | 2 ms | 调度不得阻塞 |
| `wheel_speed_limit_rad_s` | 首次调试5 rad/s，对应0.2 m/s | 与实测物理能力共同限幅 |
| `wheel_accel_limit_rad_s2` | 首次调试10 rad/s² | 同比例约束轮速变化 |
| `mit_kd` | 初值1.0 | 上机后整定，不能宣称负载下无静差 |
| `command_timeout_ms` / `feedback_timeout_ms` | 各200 ms | 独立使用无符号时间差判断 |
| `tx_busy_timeout_ms` | 100 ms | 连续忙才故障；硬件错误立即故障 |
| `state_transition_timeout_ms` | 500 ms | 启停反馈未全部确认则故障 |

车体坐标：x向前，y向左，z向上；`vx`单位m/s，正值前进；`wz`单位rad/s，正值逆时针。不提供横移速度输入。

```text
v_left  = vx - wz * track_m / 2
v_right = vx + wz * track_m / 2
wheel_left_rad_s  = v_left / 0.04
wheel_right_rad_s = v_right / 0.04
protocol_target[i] = direction[i] * side_wheel_speed * wheel_to_protocol_ratio
```

LF/LR使用左侧目标，RF/RR使用右侧目标。若任一轮超过限速，将全部轮目标乘以共同系数，不逐轮独立截断。斜坡按所有轮本周期最大变化量计算共同系数，避免限制过程任意改变转向比例。胶轮原地转向存在滑移，几何轮距仅是运动学起点，落地验收需记录实际转向效果，不宣称理想无滑移模型精确成立。

## 3. 电机接口与 C API

沿用 **MIT / Control Mode=2**，使用单独控制报文 `0x200+MotorID`、8字节。位置增益Kp=0、前馈扭矩=0，速度阻尼Kd初值1.0。单独控制要求电机固件具备对应能力，必须实测确认；不自动切换Velocity模式或写电机Flash。

参数文件仅供预期比较：速度映射±65 rad/s、Kp范围0～500、Kd范围0～5、扭矩范围±18 Nm。电机实际通信量程、控制模式和反馈ID在失能状态逐台读取确认。协议量程不代表物理最大速度；参考代码记录的约9.05 rad/s空载上限不当作已解释结论。

参数操作实行白名单。Index=0是保存操作，即使R/W=0x04也不得发送。清错必须是明确操作，不随重连自动清错。使能/失能使用`0x100+MotorID`；反馈ID必须逐台唯一可识别。本版本不采用运动广播，不能把状态查询广播中的全0未用槽当作零速度或零力矩。

接口签名约定如下，具体类型放入未来的 `chassis.h`，本次不创建底盘实现：

```c
chassis_result_t chassis_init(const chassis_config_t *config);
chassis_result_t chassis_set_twist(float vx_m_s, float wz_rad_s);
chassis_result_t chassis_set_enabled(bool enabled);
chassis_result_t chassis_stop(void);
void chassis_emergency_stop(void);
chassis_result_t chassis_clear_fault(void);
chassis_result_t chassis_get_status(chassis_status_t *out);
void chassis_tick(uint32_t now_ms);
```

- `config`按上一节定义四轮映射、方向、传动语义、限幅与超时，初始化复制配置；禁止依赖调用者之后修改内存。
- 结果至少包括OK、INVALID、NOT_READY、BUSY、FAULT。所有接口仅在同一主循环上下文调用；API非阻塞，OK表示请求被接受，不等于四轮动作已确认。
- `set_twist`只在READY/RUNNING接受有限数值，更新命令时刻；NaN/Inf拒绝且不刷新有效命令时间。非法命令在RUNNING触发停止故障，禁用状态不缓存旧目标。
- `status`提供整车状态、故障位、四轮在线/使能/温度/原始状态字、目标和实际轮速、最近反馈时间、通信故障摘要及配置确认状态。
- 初始化时允许保存尚未填齐的配置，以便诊断；使能必须拒绝未确认配置。

## 4. 状态、安全与时序

状态定义：DISABLED、ENABLING、READY、RUNNING、DISABLING、FAULT、ESTOP。

1. 上电进入DISABLED，不自动使能。低频只读查询支持诊断；所有四轮反馈均新鲜、无故障且模式/量程/轮位/方向/传动语义确认后才能接受使能。
2. `set_enabled(true)`清空旧目标，先向所有轮提交零速度控制，再提交使能；进入ENABLING。只有四轮最新反馈Bit0均为1才进入READY，500 ms内未全部确认进入FAULT。
3. READY等待**新的**`set_twist`，不能重放故障前或失能前命令；200 ms内未收到新命令进入FAULT。RUNNING每2 ms发送当前斜坡轮目标。
4. `stop()`按斜坡降至零，保持使能与速度阻尼。调用清除原运动目标；READY保持零速不因停止前命令超时再恢复运动。MIT零速阻尼不是位置锁定，也不保证斜坡上静止。
5. `set_enabled(false)`不等待斜坡，取消尚未发送的运动目标，进入DISABLING并提交失能；四轮反馈Bit0均为0后进入DISABLED，500 ms超时进入FAULT。
6. 急停立即锁存ESTOP、清空软件待发目标、取消硬件中的旧运动请求，再优先尝试零目标与失能。取消操作必须有反馈/超时，不能假设已在总线上发送的帧可以撤回。BSP后续底盘扩展须提供受控取消接口，本次只读BSP不包含该接口。
7. 任一轮反馈超过200 ms、已失能、出现故障、硬件发送错误或连续TX忙100 ms，进入整车FAULT；在线轮尝试停止/失能，不自动重试运动、不自动重新使能。
8. 故障判断排除状态字Bit0（使能标志），其他故障位按协议逐项解码。清故障只在实际原因解除、目标失能且反馈已确认后接受；重新运行必须再次使能并提交新命令。
9. 急停解除通过`clear_fault()`明确请求；若故障仍存在或任一轮状态无法确认则拒绝。解除后进入DISABLED，不直接进入RUNNING。

通讯失联时，对已断线电机不能保证失能命令送达。必须读取参数37超时和参数56保护开关Bit7，并通过物理断连测试验证。现有JSON的1000 ms只描述候选驱动超时，不能把主控200 ms检测等同于200 ms物理停车。未验证前状态报告写“驱动断线保护未验证”。急停和失能也不能替代机械制动或整车外部停机措施。

每周期只有限量处理接收帧和调度请求，ISR不解析、不打印；全部等待使用时间戳与状态机。每轮事务、全车启停事务分别有截止时间。时间戳跨32位回绕用无符号差值判断，不采用`now > deadline`直接比较。

## 5. 后续验收

| 验收项 | 通过条件 |
|---|---|
| 几何未确认 / 重复ID / NaN / 不支持固件 | 拒绝使能，无运动报文 |
| 四轮通信 | 逐轮身份、模式、量程、反馈ID与实际配置一致；1000次查询无超时/丢帧/bus-off |
| 架空轮向 | 每轮正向轮目标产生车体前进方向，反馈符号一致 |
| 直行/倒车 | wz=0，同侧与左右目标一致；落地记录实际速度、偏航和负载 |
| 弧线/原地转向 | 左右目标符合公式；正wz对应逆时针；不出现横移指令 |
| 限速/斜坡 | 所有轮不超配置上限，共同比例缩放；每周期变化不超加速度×dt |
| 使能确认 | 缺少任一轮使能反馈不得进入RUNNING；500 ms超时进入FAULT |
| 正常停止 | 清空旧目标、按斜坡到零，保持使能；无旧指令复活 |
| 急停/显式失能 | 旧待发运动帧取消，状态锁存与启停反馈检查有效 |
| 命令/反馈超时 | 最迟在阈值后的一个控制周期检测并进入FAULT；单轮掉线触发全车流程 |
| 断线保护 | 实测断线轮停车时间与驱动保护设置一致，单独报告，不能由主控日志推断 |
| 恢复/重启 | 复位上电失能；故障解除不运动，重新使能和新命令才恢复 |

当前缺失的轮距、轮位与方向由用户在实际装配后填写；实现者不得猜测默认映射。本spec中的运动验收均为后续要求，尚未进行。
